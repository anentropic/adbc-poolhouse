<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker thread → caller (exception path) | `fetch_df`/`fetch_polars` route through the single `to_thread.run_sync` chokepoint; a native `ModuleNotFoundError` (missing pandas/polars) or `AdbcError` must cross UNCHANGED. No NEW boundary beyond what `fetch_arrow_table` already crosses (RESEARCH §Security Domain). |
| task → CapacityLimiter / connection C-access | Concurrent cursor use is a C-access hazard, guarded by the reused `_offloading()` `_in_use` gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Denial of Service | poisoned connection returned to pool after a cancelled materialization | mitigate | `on_abort=self._owner.invalidate` (D-31-09) wired verbatim into both methods' `cancellable_offload` call — the identical shipped `fetch_arrow_table`/Phase 25 control, no new machinery. Proven by `test_df_cancel.py` (`adbc_cancel`-once + `invalidate` + `checkedout()==0`, asyncio AND trio, looped 20/20 in Task 2). |
| T-31-02 | Denial of Service | use-after-free / segfault reading a frame after checkin | mitigate | Approach A (D-31-01/D-31-04): the driver's `read_pandas` / `polars.from_arrow(read_all())` materialize frame-owned buffers not bound to the connection C stream — inherited from `fetch_arrow_table`/EDGE-21, no extra code. Proven by `test_df_lifetime.py`. |
| T-31-03 | Tampering | concurrent C-access on one connection | mitigate | `with self._owner._offloading():` (`_in_use` guard) brackets both methods → second in-flight op raises `ConnectionBusyError`, reused unchanged. Proven by `test_df_busy.py` (looped 20/20 in Task 2). |
| T-31-04 | Information Disclosure / Tampering | poolhouse owning the pandas/polars import site (framing where a missing-dep error surfaces) | accept (by design) | D-31-02 reason 3 / D-31-05: poolhouse deliberately does NOT own the import — the driver's lazy `import pandas`/`import polars` runs in the worker and the native `ModuleNotFoundError` propagates unwrapped. | T-31-SC | Tampering | dev-group `pandas`/`polars` (no production install in this plan) | accept (verified) | No package install occurs in this plan (landed in 31-01, dev-group only). Both are canonical top-download PyPI packages (RESEARCH §Package Legitimacy Audit: OK/OK); never a runtime import (PKG-02, D-31-08). No `[SLOP]`/`[SUS]`; no legitimacy checkpoint required. |
