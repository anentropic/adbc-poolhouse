<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → driver `adbc_ingest` (Arrow binding + SQL identifier) | `table_name`/`data`/`mode` cross into the driver untouched; the driver is the trust anchor (poolhouse adds no validation, by charter) |
| loop task → offloaded C ingest / pool connection | a cancelled mid-write must not return a poisoned connection to the pool |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Denial of Service | poisoned connection returned to the pool after a cancelled mid-write (pool starvation) | mitigate | `on_abort=self._owner.invalidate` (reused verbatim from the shipped Phase 25/29 contract) drops the poisoned connection shielded, `checkedout()→0`; proven by the 20× looped `test_ingest_cancel.py` under asyncio + trio (Task 3). No new control invented — the reused machinery IS the mitigation. |
| T-30-02 | Tampering | AST import-lint guard (PKG-03) over `_async/` after adding `functools` | mitigate | RESEARCH verified `scan_async_package` returns `[]` for a `functools.partial` file (the guard forbids only `import asyncio` / unlimited `to_thread` / `asyncio.CancelledError`); Task 3 re-runs the guard as an acceptance gate. |
| T-30-03 | Tampering | `table_name` as an untrusted identifier (potential injection if a caller interpolates user input) | accept | Consistent with the whole library's pass-through charter: poolhouse hands `table_name` straight to the driver's `adbc_ingest`, which owns identifier binding; poolhouse constructs no SQL. Documented in the docstring as a driver-level identifier, not sanitized by poolhouse. |
| T-30-04 | Tampering | concurrent C access to one connection (memory corruption) | mitigate | `self._owner._offloading()` per-call `_in_use` guard (reused verbatim) rejects a second in-flight op with `ConnectionBusyError`, race-free on the single-threaded loop; no `_reader_open` lifetime lock is taken (whole-op offload). |
| T-30-05 | Tampering | abort-the-abort (double cancellation during recovery) | mitigate | `cancellable_offload` fires `adbc_cancel` once inside `CancelScope(shield=True)` (D-25-07) — reused verbatim from Phase 25, no new surface. |
| T-30-SC | Tampering | npm/pip/cargo installs | mitigate | None occur — Package Legitimacy Audit records zero new installs; every dep is already shipped or stdlib (`functools`). No blocking checkpoint needed. |
</threat_model>
